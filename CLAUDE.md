# Brick Steps (brick-steps)

Original LEGO SPIKE Prime builds: LDraw models, kit-constrained BOM checks, building instructions and SPIKE App block missions.

## Layout

- `models/<slug>/` — one build. The slug is `<series>-<number>` (`tank-1`, shown to children as "탱크 1호"); the number counts models in a series and never changes. `model.yaml` (name, series, number, kits, status, version, created, revisions, optional `based_on` and `story.intro`), `model.mpd` (source of truth), `spec.md` (intent, mechanism, open questions), `missions.yaml` (SPIKE App word blocks shown after the finished model, ADR 0003; block ids in `src/lego_creator/missions.py`). `out/` is generated and ignored.
- `templates/` — reusable submodels to copy into a model's `.mpd` as a `0 FILE` (e.g. `lms-esp32v2-mount.mpd`); `test_real_data.py` checks they resolve.
- `inventory/<set>.csv` — kit inventories. Rebrickable sets (`<num>-1.csv`) are generated by `lc import-inventory`; other kits (`lms-esp32v2`, `tank-tracks`) are hand-written. A blank `quantity` means owned but count unknown: `lc validate` skips the shortage check and warns `quantity-unknown`. `inventory/id-map.csv` maps LDraw id → kit part.
- `ldraw/` — official LDraw library, not committed (`uv run lc fetch-ldraw`).
- `custom/parts/` — unofficial parts for non-LEGO hardware (searched after `ldraw/`, cannot shadow official parts). Generated by `scripts/gen_*.py`; regenerate rather than hand-edit. Each has a matching `inventory/<id>.csv` pseudo-kit.
- `.local/owned.yaml` — personal collection (not committed). `kits: {set: qty}` is the default for `lc new`; `model.yaml` `kits` uses the same `{set: qty}` form.
- `design/` — synced copy of the Brick Steps design system tokens (`source.json` records the artifact version). Never hand-edit; change the artifact, then re-sync.
- `scripts/` — generators for custom parts and repetitive model geometry, and `ldraw_measure.py` (part sizes, hole positions, overlap candidates).
- `docs/adr/` — architecture decisions. `docs/design-lessons.md` — what building models has taught us. `.github/workflows/pages.yml` builds and deploys the site.
- `src/lego_creator/` — `lc` CLI; `site_assets/` holds the site's component CSS, manual.js, the 3D step view (`viewer3d.js`), the service worker and `vendor/three/` (unmodified three.js, never hand-edit). `tests/` — pytest; `test_real_data.py` is skipped until `ldraw/` exists.

## Commands

- `uv run lc new <series> [--name 탱크] [--from <slug>] [--kit 45678-1 --kit 45681-1]` — the next model of a series; `--from` copies a model and records `based_on`
- `uv run lc revise <slug> -m "what changed"` — record a revision (version, date, note)
- `uv run lc list [--series tank] [--status ready]`
- `uv run lc validate <slug>` — exit 1 on any error
- `uv run lc bom <slug>`
- `uv run lc instructions <slug> [--no-pdf]` — one manual (HTML + PDF) into `models/<slug>/out/manual/`
- `uv run lc site [--include-drafts] [--no-pdf]` — gallery + manuals into `site/` (what GitHub Pages serves)
- `uv run lc fetch-ldraw`, `uv run lc import-inventory 45678-1 45681-1`
- `uv run lc release-check vX.Y.Z` — tag, pyproject and CHANGELOG agree; prints release notes
- `uv run pytest`

## Rules

- Load the `ldraw-spike` skill before writing or reviewing any `.mpd` content, and follow the `model-design` skill when creating or changing a model.
- Design know-how is kept in the repository: measurements in the `ldraw-spike` skill, design rules in `docs/design-lessons.md`, a model's unknowns in its `spec.md`. Update them in the same branch as the model change.
- A model change is done only when `lc validate` reports 0 errors.
- Improving a model is a revision of the same slug (`lc revise`); a model that adds or changes what it does is the next number in its series (`lc new <series> --from <slug>`). Never edit `version` or `revisions` by hand, and never renumber or reuse a slug.
- Hub ports are declared only in the `.mpd` (`0 !LC PORT`); do not duplicate them in `model.yaml`.
- `lc validate` checks line syntax, rotation matrices (proper rotation, det +1), color codes against LDConfig, part resolution, aliases, kit inventory, ports, the catalog fields (slug, revisions, `based_on`) and missions (known blocks, argument kinds, only declared ports). It does not check physical connectivity, collisions, grid alignment or mechanism behaviour; those need human review in a viewer (LeoCAD/LDCad) or on the real build.
- Instruction export needs LeoCAD 25.09, Xvfb and Pango (ADR 0001). The site is kid-facing Korean; only `status: ready` models are published.
- Children program in the SPIKE App with word blocks on the stock firmware (ADR 0003); the repository keeps no Pybricks programs. The Korean block wording in `missions.py` must match the app; it has not been checked against the app yet.
- The 3D step view (ADR 0002) is an enhancement over the rendered pictures and has no automated test. After changing `viewer3d.js`, `manual.js` or `pack3d.py`, build a site and check a manual in a browser.
- Site look follows the Brick Steps design system, a private claude.ai artifact (link in `CLAUDE.local.md`). Read its README before changing `site_assets/components.css`; every value there must come from a token.
- Add a line under `## [Unreleased]` in `CHANGELOG.md` in the same commit as any user-visible change. Releases follow `docs/releasing.md`: 0.0.z is the beta series and only PATCH is bumped until the maintainer says otherwise.
